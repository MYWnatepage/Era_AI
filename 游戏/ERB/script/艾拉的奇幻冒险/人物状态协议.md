# 人物状态与物品统一结算

本文件记录当前已经实现的协议。人物卡维护初始人物形象，当前状态保存实际发生的持续变化。这里只接受结构化数据，不接受脚本或文件操作。

AI在顶层JSON中返回`state_ops`数组。`story`依然是给玩家看的完整剧情，`inventory_ops`仍处理物品，`turn_id`与`base_revision`原样复制本轮user消息`program_context`中的值，`suggestions`可给0～3条后续建议。无状态变化返回`[]`；兼容旧回复省略该字段，省略不会清空有效状态。

system保存稳定任务与输出协议；最后一条user用`{program_context, player_input}`区分程序事实与玩家原话。历史只包含已经采用的玩家输入及剧情。人物卡维护形象和认识边界，当前伤势等以本地有效状态表为准，历史叙事不能代替状态入账。

## 新增

```json
{
  "op": "create_status",
  "character": "player",
  "name": "左臂划伤",
  "category": "伤势",
  "severity": "轻微",
  "description": "左前臂有浅表划伤，尚未处理。",
  "effects": "用力拉弓时疼痛",
  "reason": "本轮穿过灌木时被枝条划伤"
}
```

程序分配状态数字编号与发生时间，不接受模型指定编号或时间。同一人物同名状态应更新原记录，不能重复创建。不同人物可以有同名状态。

## 更新

```json
{
  "op": "update_status",
  "status_id": 1,
  "character": "player",
  "name": "左臂划伤",
  "category": "伤势",
  "severity": "轻微",
  "description": "伤口已清洁并包扎，尚未痊愈。",
  "effects": "用力时仍有疼痛",
  "reason": "本轮使用已有绷带处理伤口"
}
```

提供更新后的完整状态文字，保留原编号、所属人物和发生时间，由程序更新修改时间。若消耗了绷带，同一次回复的`inventory_ops`必须同时列出对应消耗；状态更新本身不会隐式扣材料。

## 移除

```json
{
  "op": "remove_status",
  "status_id": 1,
  "character": "player",
  "reason": "经过合理恢复过程，本轮确认伤口已经痊愈"
}
```

从有效状态表中移除，编号不复用；之后再次受伤可创建新记录。治疗、睡觉、切换页面和缺少状态操作都不会自动删除状态。既有剧情保留在该存档的对话历史中，状态表不另存全部已结束状态。

## 字段与结算

- `character`只允许当前剧本`characters`中登记的人物，本剧本为player、ella。world只表示无主物品，不是人物。
- 名称最多80字符，类别和程度各40字符，描述1000字符，影响500字符；影响允许空字符串。类别和程度使用文字。本剧本主角疲劳点单独保存，范围0～100，不通过状态文字给任意数值；不引入生命值或好感数值。
- 当前最多128条有效状态；物品与状态操作单轮合计最多32项。所有字段严格校验，未知字段、未知人物、错误编号、重复同名状态、过期回合等使整轮拒绝。
- 普通状态变化即使没有物品变化也需确认，预览显示状态资料和模型依据。取消不更新物品、人物状态、时间或本轮对话历史；所有操作通过并确认后才统一提交。
- `reason`是模型理由，程序不能仅凭理由验证剧情事实，采用前仍需玩家核对。
- 在场人物的全部有效状态和主角状态随本轮资料发送；场外人物在被点名或相关状态被讨论时补充。旧档场景未知时保守保留状态，避免隐藏伤势。`statuses`标记`complete:false`，未附带不代表解除，不依赖模型从旧对话推断当前伤势。只有story中描写受伤而没有状态操作，不会写入状态表。
- 状态描述与影响供AI叙事使用，不是可执行效果；当前没有自动扣血、治疗计时、技能加成或状态动画。
- 受控狩猎的`inventory_ops`和`state_ops`都必须为空，已有状态保留，并省略`scene_update`；违反时使用原骰点的本地记录结算，不接受AI额外制造伤病。

## 主角疲劳点与旧精力兼容

启用 `fatigue_rules` 后，`fatigue_points` 是主角疲劳的唯一数值来源，程序根据分段维护当前疲劳状态。AI不得新增、更新或移除主角类别为“疲劳”的状态，也不得新建主角“精力”状态。自由行动必须填写 `effort` 为 none／light／moderate／heavy，由程序换算点数，不能用状态操作绕过计算。

旧档已有的主角“精力”类记录不因名称相似被强制转换。允许用原 `status_id`、原 `character` 和原 `category:"精力"` 更新，确实消退后允许移除；不能将疲劳、伤势等改成精力，也不能将既有精力改成其他类别。休息先恢复疲劳点，再按原 `recovery_rules` 仅处理这些已有主角精力记录；不重复恢复点数生成的疲劳，不处理伤病或NPC。其他人物继续按自然状态协议维护。

旧疲劳折算时的原说明和影响在当前疲劳存续期间保留为本地来源，状态详情可查看，不逐轮发给AI；疲劳恢复到低于25点、当前疲劳完全消退后清理来源，状态表不承担永久历史档案的作用。

## 保存与兼容

状态、物品和当前场景共用SAVESTR:61存档快照、回合版本及原子提交。状态字段为`characters`、`statuses`、`next_status_id`。每条状态保存id、character、name、category、severity、description、effects、created_at、updated_at。

采用后更新内存进度，自动保存开启时按既有回合流程保存，也可以手动保存。读取旧进度恢复当时状态，新游戏清空本局状态；无独立公共状态文件。旧档没有这些字段时补空表，不重置物品，不从旧剧情猜测人物伤势；损坏状态会报错，不能静默覆盖。

## 与当前场景的关系

`scene`保存当前地点、在场人物编号和场景摘要，新游戏初始化读取剧本`initial_scene`，旧档未记录则保持未知。人物卡存在不代表该人物在场；场景更新也不会自动移除其有效伤势。

AI可附带`scene_update:{location,present_characters,summary,reason}`。地点或在场人物改变进入统一采用确认，仅更新摘要不强加确认；省略保留现状。此字段不能修改伤势、物品或时间。本剧本的狩猎、入眠与短休结束均停留原地；允许地点由`action_locations`配置，程序执行前复核，不由AI绕过。

场景只帮助叙事连续，不是地图、距离或事件引擎。程序校验字段、编号和已登记数据，模型理由不代表已经证明全部剧情事实。剧本提供人物、关系与行动内容，框架处理通用结构、局部上下文筛选与存档。
