# 艾拉的奇幻冒险：维护说明

本文件面向剧本作者，只说明当前剧本资料和规则。玩家操作见同目录[剧本说明](剧本说明.md)，通用结构化字段见[AI交互协议](AI交互协议.md)，新剧本接入见[开发说明](../../../../docs/开发说明.md)，输入、确认与保存流程见[剧情输入与本地状态](../../../../docs/剧情输入与本地状态.md)。历史修改与验证范围统一见根目录[更新记录](../../../../更新记录.md)。

## 剧本身份与人物

- 显示名：艾拉的奇幻冒险；类型：测试；作者：Natepage。剧本自己的版本标记与软件0.3.0版本分别维护。
- 内部编号保持 `rain_room`，兼容旧标题“雨夜房间”和既有存档。改显示名不应改内部编号。
- 欧洲中世纪奇幻世界；少年猎人在七年前的暴雨夜救下女婴艾拉，两人相依生活。主角当时约四岁，早年照料条件、外援与眼镜来源尚未设定，AI不得自动补成穿越或其他背景。

| 人物 | 初始资料 | 形象与层级 |
| --- | --- | --- |
| 主角 `player` | 11岁，145 cm，36 kg，健康 | 黑发，现代树脂镜片眼镜，沉稳；主要人物，台词和决定由玩家给出 |
| 艾拉 `ella` | 7岁，120 cm，22 kg，健康 | 红发、有雀斑，开朗、好奇；主要人物，对婴儿时期没有亲历记忆 |

`人物卡.ERB`维护初始身份、外貌、性格、认识边界、关系、说话习惯和摘要。基础资料与开局健康在新游戏建立本局人物资料；游玩中的伤势、所在地、物品和疲劳不写回初始卡片，也不因重新查看卡片恢复健康。人物详情的“健康”来自开局基线或当前状态，不代表建立了生命值系统。

新具名人物通过确认后的 `character_ops` 登记到本局，默认为次要人物。玩家可在详情中调整本局新增人物层级，初始主角与艾拉的层级由剧本指定；伤势、位置和物品记账不因主要／次要而省略。

## 初始物品与汇率

初始11种物品：铜钥匙2把、食材10份、金币2枚、银币36枚、铜币81枚、左轮手枪1把、子弹5发、高碳钢长矛1把、复合弓1把、弓箭3支、毽子1个。毽子归艾拉，其余归主角。武器不预设口径、装填数量或伤害。

`剧本.json.parameters`中 `silver_per_gold=100`、`copper_per_silver=100`，即1金币=100银币、1银币=100铜币；初始钱币合计23681铜币。币种数量以当前物品表为准，不另设旧引擎MONEY余额。汇率不放物品描述中，也不代表已经实现固定商店、价格或自动找零。

新游戏从卡片复制物品；开始后的数量、归属和新物品描述在本局快照维护，修改模板不改写已开始的存档。初始归属为 `player`、`ella`、`world`，已确认的新人物也可成为物品持有人；类型为消耗品、普通物品、特殊物品。定义与各归属数量在同一条记录中，部分转交沿用编号，数量为0仍保留定义。字段和上限统一见AI交互协议。

## 时间、食材和行动

一天8行动点，短休和普通交谈／自由行动通常用1点，狩猎用4点；地图移动按贴地距离每500米用1点，小数消耗累计到整点。入眠结束当天，清除当日小数消耗，第二天恢复完整行动点。普通AI回复失败、取消、空输入或核心结算不合法不推进时间；只读物品、人物、历史、记忆和存取菜单不消耗时间。

每日结束消耗2份食材，优先主角、其次艾拉持有的食材，无主食材不计家庭储备；食材合计归零结束本次游戏。初始10份且没有补充时，第5次每日结算耗尽。每日结算由程序执行，AI不得重复扣粮。

| 菜单 | 当前规则 |
| --- | --- |
| `[1] 自由输入` | 先关联物品，再输入原话或选择建议；关联不等于已经消耗或转交 |
| `[2] 入眠` | 仅森林边的小屋开放，结束当天并结算食材 |
| `[3] 休息` | 当前允许地点原地短休1点，不传送、不治疗伤势 |
| `[4] 移动` | 打开原生地图，按路线距离结算 |
| 分割线下 `[5]` | 狩猎林地显示狩猎，村落集市显示交易 |
| `[6]`～`[12]`、`[0]` | 保存、读取、历史、物品、人物状态、历史记忆、场景，以及返回标题 |

不能执行的选项保留编号，显示原因，没有焦点且不可选。地点允许范围由 `action_locations` 控制，特殊行动名称与输入由 `location_actions` 提供。已知五个地点均允许休息和移动；野外允许休息、移动，没有小屋加成，不能借靠近建筑执行入眠或狩猎。

物品矩阵首次点击选择1，左键加1、右键减1至取消；悬停时↑／↓每次加减10，最多为可用库存。可多选，数量表示本轮关联范围；只读背包仅查看详情。界面操作与通用确认流程见根目录使用说明和剧情输入文档。

## 地图、地点与人物所在地

`场景卡.json`由 `world_file`引用，维护初始描述、设施和规则；`地图.json`维护布局。当前人物所在地、设施状态和本局新地点随快照保存，人物卡或地点卡存在不代表人物已在场。旧默认描述仅按 `description_migrations`精确匹配更新，自定义内容保留。

地图按住右键绘制贴地路线，起点固定为当前坐标；左键单击锁定路线后，点击“开始移动”才结算。已有路线时右键单击清除，左键拖动旋转、滚轮缩放。终点可以是任意有效地面坐标，不必是固定地点；区域外记为野外。只读“查看场景”不执行移动。

程序重算距离与费用，检查起点、预算、路线连续性及修订号，不接受AI或界面自报费用。仅移动主角，其他人物保留实际所在地。`player_position`保存实际X/Z、地点与野外标记；`movement_remainder`保存不足整点的消耗。只有整点部分交给时间函数推进，短路不强扣整点。

AI的 `scene_update`只能维护当前已确认主角地点内的情况，不能跨地点传送主角、移除主角在场或清除坐标。地点详情依次显示名称／坐标、简述、实际人物、带方括号的地点专属行动和特殊增益，不罗列通用菜单。人物离开须明确去向，场景变化与其他本局变化一起确认。

## 狩猎与疲劳

每天最多完成一次狩猎，需至少剩余4点且位于狩猎林地。通过检查后掷一次D20，以行动前疲劳计算减值，有效点数最低为1：

| 有效点数 | 结果 | 食材增加 |
| --- | --- | ---: |
| 1～3 | 空手而归 | 0 |
| 4～8 | 少量收获 | 1 |
| 9～14 | 有所收获 | 3 |
| 15～18 | 收获颇丰 | 5 |
| 19～20 | 满载而归 | 8 |

程序发放食材，模型只描写同一结果，不追加收益、扣弹药、损坏武器、制造伤病或移动人物。请求失败、取消、截断、格式无效或额外操作时，仍按同一骰点结算一次本地简短记录，不重掷、不重复奖励。结束留在猎场。骰表、叙事模板与数量检查规则在 `剧本.json.actions.hunt`维护。

主角启用 `fatigue_rules`，新局0点，范围0～100；当前数值是唯一来源，程序派生状态，AI不能直接增删改主角疲劳或新增主角精力记录。艾拉和其他人物仍维护自然状态，不共用主角疲劳点。

| 主角疲劳点 | 状态 | 骰点减值 |
| --- | --- | ---: |
| 小于25 | 精力尚好 | 0 |
| 25至小于50 | 轻微疲劳 | 2 |
| 50至小于75 | 中度疲劳 | 4 |
| 75～100 | 重度疲劳 | 6 |

- 移动每500米增加5点，按实际距离保留小数；完成狩猎增加25点。
- 自由行动由AI填写 `effort:none/light/moderate/heavy`，程序分别换算0／5／10／20点；交谈、询价、咨询、计划、否定及假设为none。仅陈述累或不累不直接改数值，实际疲劳变化与其他提案一起确认。
- 短休恢复15点，小屋额外10点，共25点；入眠基础恢复60点，小屋额外20点，共80点，目前入眠仅在小屋可执行。恢复限制在0～100，不能因此治疗伤病或改变其他人物状态。
- 判定保存原骰面、疲劳减值和有效点数。动画展示原骰面，收益／处理质量使用有效点数。行动后的疲劳只结算一次，不反过来改变该次判定；已接入的掷骰包扎同样使用行动前减值。
- 入眠、休息和移动使用本地文本，不调用AI；入眠与休息文案按已完成回合进度轮换，模板见[入眠与休息模板](../../../../docs/入眠与休息模板.md)。

行动点条为8格剩余量，疲劳条为10格累计量，均支持小数局部填充和状态颜色。D20等待AI时持续转动，回复或失败、取消后停稳显示同一原骰面；其他骰子模型和设计预览保留，但游戏不提供切换或重掷入口。

## 本局状态、记忆与存档

伤势等当前记录使用 `state_ops`，同一处伤势沿用编号，描述可自然调整。仅咨询治疗不入账，实际包扎不等于痊愈；明确程序包扎由程序保护同一材料与目标伤势，避免AI重复扣除或解除。人物资料、伤势和实际所在地分开保存，不从历史剧情猜测未记录的状态，也不引入生命值或好感数值。

历史记忆与原始对话分开。玩家可添加、编辑、置顶、停用摘要，AI只能提出待确认建议；采用后才按相关性和明确到期日召回。摘要不能覆盖当前库存、伤势或位置，日期到达也不等于完成约定。细节和示例见剧情输入文档及AI交互协议。

| 内部位置 | 用途 |
| --- | --- |
| `SAVESTR:60` | 当前AI对话历史快照，随存档保存与恢复 |
| `SAVESTR:61` | 本局统一JSON：物品定义／数量、人物资料与状态、动态人物、场景、记忆、疲劳、坐标、小数消耗及修订号 |
| `SAVESTR:62`、`:66`、`:68` | 最近变更摘要、建议行动JSON、最近行动摘要 |
| `FLAG:20`、`:21`、`:22` | 食材显示缓存、旧食材迁移标记、最近每日结算日期 |
| `FLAG:24`、`:25`、`:26` | 时间格式版本、每天格数、狩猎耗时 |
| `FLAG:30`～`:35` | 已掷骰点、收获、最近狩猎日期、已掷骰日期、行动种类及耗时 |

采用后先更新内存进度，执行自动或手动保存才进入对应 `.sav`。新存档位于 `游戏/数据/存档/rain_room/`；旧根目录存档保留并按登记别名读取，之后保存到新目录。框架服务与存档隔离约定见开发说明。

维护旧档时遵循以下边界：

- 缺当前物品表时才复制初始11种；已有食材记录保留实际余量及已结算日期，没有旧食材记录则从初始食材接入，不追扣历史日期。旧档从未保存的新物品无法凭空恢复。
- 旧4时段时间首次按 `TIME×2`迁移到8点，不重复转换或追扣食材。已有快照读取后保留当时数量、人物、日期和修订号，损坏或未知版本报错，不静默重建覆盖。
- 旧档没有场景时保留未知，不回放开场；新游戏才建立初始小屋场景和开局健康。旧档补基础人物资料不会擅自补出“当时健康”。
- 旧主角轻／中／重疲劳首次约折算25／50／75点，未知程度按75点保守处理，已有点数不重复转换。旧来源保留至当前疲劳消退；旧精力仅沿原类别维护并按兼容恢复规则缓解，不与派生疲劳双算，其他人物和伤病保持独立。
- 对话历史读取存档快照，缺完整快照时仅恢复旧存档实际保存的短期记录，不恢复未来对话或别局进度。配置、API密钥与显示选择不写进剧本初始卡片。

## 当前限制

物品、人物状态、当前场景、动态人物、历史记忆与路线移动已经接通。固定商店库存与价格、自动找零、完整剧情事件／任务表和战斗数值判定仍未实现；普通AI理由和人工确认不能证明交易来源或全部叙事事实。狩猎暂不自动消耗弹药、损坏武器或产生伤病。后续工作集中见[开发路线图](../../../../docs/ROADMAP.md)。
