# 发布检查清单

## 1. 固定源码

- 明确版本范围、已知限制和存档兼容性。
- 确认主分支自动检查通过，必要的引擎测试和人工验证已完成。
- 检查未提交改动，不将开发中的个人工作混入发布。
- 将主菜单、关于、窗口与程序版本、README 和更新日志同步。

## 2. 构建与清理

- 从将要打标签的干净源码提交构建。
- 新建发布暂存目录，只复制允许公开的游戏文件和必需依赖。
- 不直接压缩实际游玩目录；不包含个人配置、密钥、存档、日志、对话、用量或缓存。
- 使用明确的公开默认设置，扫描密钥特征、个人路径、调试符号和异常文件。
- 核对新增依赖与素材许可，保留版权及第三方声明。

## 3. 验证包

- 解压到独立目录，检查首次启动、版本、空白连接和默认设置。
- 运行相关核心、引擎与存档回归；真实 API 测试另外记录费用和范围。
- 验证压缩完整性，生成 SHA256 校验文件。

## 4. 发布

- 版本标签必须指向对应源码提交；不要用旧提交给新运行包打标签。
- 以 Alpha / 预发布状态发布当前开发测试版本。
- 上传玩家包、校验文件和更新说明，核验线上附件及哈希。
- 发现既有版本说明错误时优先补充更正，不悄悄移动已经公开的标签。
- 更新 README 推荐入口、CHANGELOG 和任务状态。

## 5. 发布后

- 核对新旧版本都能单独访问。
- 在自己的 IDE 仓库 Fetch 更新提交记录；不要以 Reset 或覆盖工作文件代替 Fetch。
- 收集问题进入 Issues，确认严重回归后再决定修复版。
