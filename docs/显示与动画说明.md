# 显示与动画说明

本文面向维护者，记录剧情显示、骰子动画与原生地图展示的职责边界。玩家操作见[使用说明](../使用说明.md)，剧本接入见[开发说明](开发说明.md)。

## 剧情接收与本地显示

设置首页「[8] 剧情显示」管理一起显示、逐字显示及速度，摘要同步展示实际方式、非流式接收和适用速度。设置首页依次编号1～17，0返回。

| 项目 | 当前行为 |
| --- | --- |
| 回复接收 | 网络请求使用非流式，先收完整回复再校验和展示 |
| 流式页面 | 仅显示“（未完成）”，查看它不会启用流式或修改已保存选择 |
| 一起显示 | 默认方式，完整展示剧情 |
| 逐字显示 | 按完整文字元素推进，不拆开表情或组合字符 |
| 显示速度 | 1～120字/秒，初值30；拖动滑块、↑↓或滚轮每次调整5，或输入数值回车应用 |
| 模式切换与返回 | 左右键切换方式；一起显示时保留逐字速度；输入0或Esc返回 |
| 播放时补全 | 回车、空格、Esc或点击补全；此次输入被消费，不继续选择下一项，也不取消已收剧情 |

配置位于游戏目录的`配置/narrative-display.json`，独立于剧本和存档。缺失或损坏时回退到一起显示、30字/秒，其他显示和模型配置保持原样。改变本地显示不改变生成预算、回复长度或Token消耗。

### ERB接入

`NARRATIVE`接收纯剧情文本开始展示，`NARRATIVEPOLL`返回1为完成、0为仍在播放。剧本应持续轮询，在播放完成前不放行下一次行动：

```erb
NARRATIVE LOCALS:0
$NARRATIVE_WAIT
NARRATIVEPOLL
IF RESULT == 0
    TWAIT 16, 1
    GOTO NARRATIVE_WAIT
ENDIF
```

这两个命令不调用API，不推进时间，不提交或撤销本局状态。需要确认的回复先在确认页阅读，再决定采用或取消；结果页以及查看物品、人物后返回时，不重复播放已读剧情。历史对话保持完整显示。

播放器使用正常游戏文字画布，只更新末尾未完成段落；完整段落保留在显示记录中。重入刷新等待下一次轮询，避免重复绘制或提前开放菜单。完整剧情按原流程保存，播放进度不写入游戏存档。

| 源码位置（相对于`源码/Emuera/`） | 职责 |
| --- | --- |
| `NativeDisplay/NarrativeDisplaySettings.cs` | 设置读写、文字元素推进、补全 |
| `NativeDisplay/NarrativeDisplayEditor.cs` | 显示方式和速度编辑器 |
| `UI/Game/EmueraConsole.Narrative.cs` | 游戏画布中的播放、刷新与完成判断 |
| `UI/Framework/Forms/MainWindow.Narrative.cs` | 输入保护和跳过播放的交互 |
| `Runtime/Script/Statements/Instruction.NativeDisplay.cs` | `NARRATIVE`与`NARRATIVEPOLL`桥接 |

## D20骰子动画

正式游戏只启用D20展示，不提供玩家骰型切换、自定义点数或重新投掷入口。D4、D6、D8、D10、D12、D20模型和[独立设计预览](设计预览/掷骰动画.html)保留，供作者后续开发。

### 生命周期

1. 程序先确定本次骰点与规则结果，再把同一结果发送给AI并交给动画。
2. 起始快速旋转、轻微弹跳；等待回复时持续较慢旋转，不重复掷骰。
3. 收到完整回复，或失败、取消、超时后，约0.7秒停稳，再高亮原点数约0.9秒。
4. 动画结束后显示同一份剧情或原规则的本地保底结算；即使服务立即返回，也保留停稳和结果展示。

动画表面显示原始骰面。启用疲劳减值时，玩法按扣减后的有效点数结算，最低为1；结果摘要区分原始点数、减值和有效点数。展示不会再次扣减或重新掷骰。

等待时按Esc或点击中止请求，行动如何结算由原规则决定。喇叭仍可使用；动画期间不开放消耗图表或新的行动输入。窗口改变后按当前区域重绘，结束或关闭时释放计时器。

动画只展示已确定结果，不生成随机数、不修改物品或存档、不按自然语言重判，也不额外请求AI。普通对话、连接测试和不含D20判定的行动不触发动画。

| 源码位置（相对于`源码/Emuera/`） | 职责 |
| --- | --- |
| `NativeDisplay/DiceGeometry.cs` | 六种骰子的顶点、面、编号及停稳方向，不含具体剧本规则 |
| `NativeDisplay/D20Animation.cs` | 旋转、等待、停稳、高亮和主题绘制 |
| `UI/Framework/Forms/MainWindow.Dice.cs` | 窗口计时器、输入保护、取消与资源释放 |
| `NativeAI/AiRuntime.cs` | 将已确定的D20结果交给展示层 |
| `Runtime/Script/Statements/Instruction.NativeAI.cs` | AI请求与动画衔接，`AIPOLL`等待展示完成后放行同一回复 |

骰点、收益、耗时及失败后的玩法结算留在剧本和其规则服务中。若修改动画时长，应核对请求等待、取消、失败和结果放行过程，避免重掷、重复收益或跳过展示。

## 地图与其他原生展示

生产地图使用C#与Windows OpenGL/WGL绘制；网页地图文件保留为测试和迁移对照，不嵌入正式程序。旋转、缩放、主题配色、地点焦点和长介绍滚动属于显示层，实际位置、路线消耗及地点能力由本局数据与移动服务决定。

地图7:3区域布局、兼容绘图回退及路线操作见[使用说明](../使用说明.md)；原生化前后的资源测量见[地图性能对比](地图性能对比.md)。行动点和疲劳框是按当前字体定位的矢量显示，包含小数填充，不产生可点击选项。

## 相关验证

剧情显示测试覆盖默认值、配置恢复、完整文字元素、一起/逐字、补全、确认页和返回后不重播。骰子测试覆盖几何、20个结果、长等待、停稳、重复完成、取消/失败、配色和窗口尺寸；隔离行动测试检查动画结束后不重掷或重复发放收益。实际测试入口见[开发说明](开发说明.md#修改与验证)，历史测试结果见[更新记录](../更新记录.md)。
