# 剧情显示

设置首页的显示设置中提供「[8] 剧情显示」，摘要同步展示当前方式、非流式接收及适用的逐字速度。设置菜单按页面顺序编号1～17，最后为0返回。

「回复接收」提供非流式和流式两个页面。非流式已有完整功能；流式页面下方只显示「（未完成）」，作为后续功能入口预留，查看该页面不会启用流式或改变已有显示配置。当前API仍以非流式接收完整回复，再按所选方式在本地显示；此设置不改变生成参数、回复长度或Token用量。

- 一起显示：完整展示，作为未配置时的默认方式。
- 逐字显示：按完整文字元素推进，不拆开中文、表情或组合字符。
- 速度：1～120字/秒，初值30。可拖动滑块、使用↑↓或滚轮每次调整5字/秒，或输入数值回车应用。
- 一起显示时不调速度，但保留之前设置；左右键可切换模式。输入0或Esc返回设置。
- 播放时按回车、空格、Esc或点击剧情补全文字，这次操作不选择下一项，也不取消已接收的剧情。

设置保存在游戏目录的`配置/narrative-display.json`，与剧本和存档独立。缺失或损坏配置回退到一起显示、30字/秒；不覆盖其他显示设置或API配置。

## 剧本接入

框架提供通用`NARRATIVE`和`NARRATIVEPOLL`命令，接收纯剧情文本，不依赖具体人物、物品或剧本名。前者开始显示，后者返回1表示完成、0表示仍在播放。剧本在完成前使用短暂等待继续轮询：

```erb
NARRATIVE LOCALS:0
$NARRATIVE_WAIT
NARRATIVEPOLL
IF RESULT == 0
    TWAIT 16, 1
    GOTO NARRATIVE_WAIT
ENDIF
```

命令不调用API，不推进时间，也不提交或撤销状态。AI回复仍需完整校验；需要确认的回合先在确认页阅读剧情，再由玩家决定采用或取消。已经在确认页读过的剧情进入结果页，以及查看物品或人物后返回，不重复播放；历史对话保持完整显示。

播放过程使用正常游戏文字画布，只更新末尾尚未完成的段落，完整段落保留在显示记录中。刷新期间的重入会等待下一次轮询，避免补全文字时重复绘制或提前放行菜单。完整剧情仍按原有流程保存，显示进度不写入游戏存档。
