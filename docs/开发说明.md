# 开发说明

本文面向框架维护者和需要深入定制的剧本作者，记录0.3.0的当前结构与接入约定。从零制作剧本请先阅读[剧本制作指南](剧本制作指南.md)，本页提供技术参考。玩家操作见[使用说明](../使用说明.md)，一轮对话的资料与保存流程见[剧情输入与本地状态](剧情输入与本地状态.md)，展示层接入见[显示与动画说明](显示与动画说明.md)。

## 目录和职责

| 位置 | 维护内容 |
| --- | --- |
| `源码/Emuera/` | C#运行器、AI服务、校验、原生显示、地图与存档桥接 |
| `游戏/CSV/GameBase.csv` | 项目名称、作者、版本等元数据 |
| `游戏/ERB/`第一层 | 框架菜单、设置、剧本发现及通用流程 |
| `游戏/ERB/script/<剧本名>/` | 本剧本的初始资料、规则、入口和本局状态维护 |
| `测试/` | 核心模拟测试及隔离运行器测试 |
| `游戏/配置/`、`游戏/数据/` | 使用时生成的个人配置、存档、历史及用量，不进入源码提交 |

框架提供显示、声音、模型连接、AI协议校验、状态快照、地图与存档服务；故事、人物、物品含义、行动消耗、每日结算及结局由剧本维护。主菜单、设置、游戏说明和关于可以共享通用函数，不依赖某个剧本。

## 剧本登记参考

一个剧本包位于`游戏/ERB/script/<剧本名>/`，由`剧本.json`登记，其余ERB由作者组织。逐步创建文件、可复制的林间驿站示例、首次运行和打包方法集中在[剧本制作指南](剧本制作指南.md)。添加剧本无需修改框架菜单或重新构建运行器。

登记中的`entry`、`resume`为必需函数名；`init`、保存/读档等其他生命周期钩子可省略。所有已填写的函数须在本包内定义；省略可选钩子不会自动获得某套生存规则。

添加或移走整个包后重启游戏。登记缺损、入口不存在或编号重复会在剧本选择页提示；编号重复的包均不载入。各包ERB仍使用引擎的统一解析环境，函数应使用独立前缀；包之间的模块划分不等于进程级隔离。

### 登记资料

| 字段 | 用途 |
| --- | --- |
| `id` | 1～64位英文字母、数字、下划线或短横线组成的稳定编号，不能因改显示名而随意更换 |
| `owners` | 物品归属编号与显示名；仓库、无主等无需成为人物 |
| `characters`、`major_characters` | 初始人物登记及主要人物；未登记状态功能的旧包可保持空人物表 |
| `content` | 作者维护的文字资料键值表 |
| `parameters` | 剧本整数规则；编号、汇率和食材含义不属于框架约定 |
| `world_file` | 包内场景卡JSON，包含`format_version:1`和`scenes`数组 |
| `initial_scene` | 显式新游戏使用的初始地点、在场人物和摘要 |
| `context_selection` | 相关物品别名、关联物品及行动物品选择规则 |
| `inventory_instruction`、`actions` | 本剧本结算限制、受控骰表、收益及保底叙事 |
| `action_locations`、`location_actions` | 行动允许地点及地点专属入口 |
| `recovery_rules`、`fatigue_rules` | 可选的恢复和疲劳规则 |
| `item_text_migrations_file` | 只匹配原默认文字的迁移表，避免覆盖自定义描述 |

人物卡、物品卡是作者组织内容的方式，并非所有剧本必须采用相同文件或玩法。当前艾拉剧本的背景和开场在`content`，人物在`characters`，汇率与日常消耗在`parameters`；`剧本接口.ERB`负责读取资料和组装材料，`生命周期.ERB`负责初始化、迁移、回合钩子及兼容入口。其历史编号`rain_room`为兼容旧档保留。

## 生命周期和本局数据

| 字段 | 调用时机 | 约定 |
| --- | --- | --- |
| `init` | 新游戏开始 | 初始化此剧本状态，成功返回1，失败返回-1 |
| `entry` | 初始化成功后 | 进入本剧本流程 |
| `resume` | 读档恢复完成后 | 继续流程，不重新发放初始物品 |
| `before_save` | 手动保存说明生成前、自动保存前 | 将需随档保存的外部状态写入本剧本字段，成功1、失败-1 |
| `after_load` | 引擎恢复存档后 | 校验、迁移、恢复历史等，成功1、失败-1 |
| `turn_end` | `EVENTTURNEND` | 由剧本决定时间、消耗和结局 |
| `save_caption` | 生成存档标题时 | 写入`RESULTS:0`并返回1；未提供时使用剧本名称 |
| `legacy_probe` | 旧档缺少剧本编号时 | 匹配返回1，否则0；只有唯一匹配才采用 |

通用层保留`SAVESTR:0`作为本局剧本编号。其余FLAG、SAVESTR下标由剧本定义，必须在自己的初始化中设置。`GLOBAL`、配置、显示和模型连接为共用设置，不用于跨存档保存本局库存。艾拉示例将物品、人物状态、位置、人物资料和长期记忆统一放入`SAVESTR:61`，其他剧本可自行选择存档字段。

- 正常存档位于`游戏/数据/存档/<id>/saveXX.sav`；使用自定义存档根目录时相对于该目录。各包同号手动存档及99号自动存档互不覆盖。
- 新标题带`[scenario:<id>]`，依编号分组。旧根目录存档不移动或删除；本包目录没有同槽存档时，按`legacy_save_labels`读取旧档。新保存不覆盖旧根目录文件。
- 已采用对话位于`游戏/数据/记忆/<id>.json`。剧本应在保存/读取钩子中捕获和恢复对话快照，使读档不带入未来对话；显示标签使用`reply_label`。
- 存档保存当前实例，不复制整套初始ERB。修改初始卡片不会回写已有存档；编号、归属或字段变化须提供迁移方案。缺少场景的旧档保留未知，不重放开场。

## 资料选择与结算边界

system保存稳定任务及输出协议；最终user是`{program_context, player_input}`，区分程序事实与玩家原话。历史只包含已采用输入和剧情。不要在ERB材料中重复整套初始库存、开场或玩家原话。

`context_selection.item_aliases`、`related_items`、`action_items`分别配置物品别名、关联编号和行动相关物品。原生层结合当前选择及最近已采用对话，在本地筛选资料，不为筛选额外调用模型。局部表会标明范围，未列出不等于不存在；合法性仍对完整快照校验。指代不明时应确认，不能猜编号。

AI仅提出变化，普通变化经统一预览、玩家采用及版本校验后提交；无变化不强加确认。程序受控行动先确定并保留骰点、收益，再向AI提供事实，不能由AI额外发放同一次收益。完整JSON字段与边界见[AI交互协议](../游戏/ERB/script/艾拉的奇幻冒险/AI交互协议.md)。

场景卡包含数字`id`、`name`、`description`、`adjacent`、`facilities`、`aliases`和`rules`；编号、名称、别名不得冲突。场景首次复制后，本局维护已知场景、各人物位置和地点近况。自由输入的`scene_update`只能在主角当前地点内维护场景，跨地点移动由地图结算；其他人物不会自动同行。剧本可不配置固定场景卡，但不能因此假定旧档仍处于开场。

所选字符串兼容旧编号CSV，新写法为`id:数量,其他id:数量`。最多关联16种，首次左键选1，左键+1、右键-1，悬停时↑/↓每次加减10；最多为可用库存，减至0取消。选择只存在于本次输入页，不写入本局快照。85的只读详情按钮值为`10000+物品ID`，选择payload为`@item:编号`；选择不自动消耗。
