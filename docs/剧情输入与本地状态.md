# 剧情输入与本地状态

本页说明一次行动如何变成剧情和本局记录，不重复列出全部字段或玩法数值。初始资料属于剧本，本局发生的事实由程序保存，AI根据本轮相关资料续写剧情并提出变化。

- 玩家操作见[使用说明](../使用说明.md)。
- 开发接入见[开发说明](开发说明.md)。
- 完整字段、操作和限制见[AI交互协议](../游戏/ERB/script/艾拉的奇幻冒险/AI交互协议.md)。
- 艾拉剧本的具体规则和维护入口见[剧本维护说明](../游戏/ERB/script/艾拉的奇幻冒险/说明.md)。

## 初始资料与本局进度

开始新游戏时，剧本读取初始背景、人物、物品及场景资料，构建本局快照。人物卡描述人物形象，初始物品卡描述物品定义和起始持有量；游戏中的新物品、人物、状态和经历写入本局进度，不反写初始卡片。

读取存档恢复的是当时的本局资料。初始文件后来修改，不等于已有存档自动重开；兼容处理只补充规则允许的缺失资料，不重置已有库存、伤势或人物经历。

## 一次普通自由行动

1. 玩家在行动页选择本轮相关物品及数量，再输入原话或点击建议。选中只表示关联，不代表已经消耗或交出物品。
2. 程序从本地进度挑选相关人物、物品、场景、有效状态、记忆及近期对话，组成请求。
3. AI返回完整剧情，以及需要程序核对的数据变化和建议。
4. 程序先检查回合标识、数据结构、有效编号、库存和规则。核心操作不合法时不提交这一轮；可选建议按各自的容错规则处理。
5. 普通事实变化进入候选快照，玩家采用后才整体提交；取消不会将候选物品、人物状态或时间写入当前进度。无需事实确认的回复按现有流程采用。
6. 已采用的剧情写入历史，本局状态更新；执行自动或手动保存后，当前快照进入对应存档。

查看候选物品或人物保持只读，不会提前采用提案。界面只展示正文和可读的变化，结构化字段供程序核对，不作为剧情内容显示。

## 每轮交给AI什么

`system`放稳定的续写任务、输出格式和约束；最后一条`user`分为程序资料`program_context`与玩家原话`player_input`。已采用历史作为资料进入请求，不把旧剧情当作本轮输出格式。

程序按需提供：

- 精简的背景、人物认识边界、当前时间和适用规则。
- 当前场景、在场人物，以及被本轮点名或明确关联的目标。
- 选中物品的完整资料与关联数量，其他相关物品作为补充，不重复发送同一张卡。
- 相关人物的有效状态，以及按主要、次要层级整理的已知人物资料。
- 相关或到期的已确认记忆，以及按设置和预算选入的近期连续对话。
- 若程序已经确定骰点、用法或收益，附上对应结果，让AI围绕同一结果描写。

没有选入的物品或状态仍保存在本地，不能理解为数量为零、已经解除或不存在。整张地图、全部库存和全部历史不会因为保存在本局而每轮完整发送。人物资料不代表人物在场，当前所在地由本局记录决定。

## AI回复与软件操作

`story`是给玩家看的完整剧情；物品、人物状态、场景、人物登记等字段是提案。软件只识别允许的数据操作，不执行AI返回的脚本或任意文件指令。支持字段、字数和数量上限集中维护在[AI交互协议](../游戏/ERB/script/艾拉的奇幻冒险/AI交互协议.md)。

程序可以核对结构、编号、数量、归属、回合版本及已接入规则，但不能保证理解所有自然语言。剧情中的物品获得、伤口处理和其他变化仍应与提案一起核对。AI不得借场景提案跨地点移动主角，实际移动由地图流程结算。

例如，玩家选择一份布条并输入“我用它包扎左臂的伤口”：本轮提供所选布条、对应伤势和必要场景资料，AI提出与直接处理相符的剧情、材料变化及原伤势更新，程序校验后供采用。包扎不等于痊愈，已有伤势应沿用原编号；如果只是询问“该怎么处理”，应提供建议而不预先消耗物品。

明确选择程序提供的包扎用法，则由该用法维护材料消耗、目标和可选骰点；AI不能重复扣除已经由程序结算的材料。

## 程序行动与普通回合的区别

移动、入眠和短休直接由本地规则执行，不请求AI。地图移动按贴地路线重新测距，保存实际终点和小数行动点；具体限制与恢复数值由所选剧本决定。

狩猎先由程序确定骰点和收获，动画与AI使用同一个结果。已确定的受控狩猎即使取消等待、网络失败或回复无效，也按同一结果完成一次本地结算，不重新掷骰或重复发放。不能把普通自由回合的取消行为套用到这类程序行动。

疲劳、材料和每日食材等已接入的数值由程序维护；AI提供活动强度等协议字段时，程序再按剧本规则换算。字段和兼容约束见协议，当前艾拉规则见[使用说明](../使用说明.md)。

## 历史对话和长期记忆

历史对话保存已经采用的玩家输入与剧情。长期记忆是另行采用的简短摘要，不替代当前库存、伤势、位置等账本。

玩家可以手动添加摘要，或从近期已采用对话中摘录；AI也可以随回复提出记忆建议。采用剧情后，AI建议先进入待确认列表，只有在历史记忆页明确采用后，才用于后续召回。编辑记忆后仍需保存进度，读旧档会恢复当时的记忆。

例如第2天答应第3天带艾拉去集市，可以记录：

> 第2天，主角答应第3天带艾拉去集市，尚未履行。

关键词使用“集市、约定、第3天”。AI提出的建议在日期明确时可带`due_day: 3`；采用后，可因相关输入或游戏日期被召回。到期不代表已经履行，不会自动移动、付款或完成任务。履约后更新摘要，并将不再需要的提醒标记失效。无日期的旧摘要继续按相关性检索，不从文字中猜出履约日期。

## 保存位置

以下是当前艾拉剧本的保存约定；`SAVESTR:60`和`SAVESTR:61`并非框架强制保留字段，其他剧本可在自己的生命周期钩子中采用不同字段。

| 内容 | 保存位置 |
|---|---|
| 初始背景、人物、物品和场景 | 剧本文件夹中的卡片与JSON |
| 当前物品、新人物档案与层级、持续状态、疲劳、场景、实际坐标、小数行动点、人物所在地、设施状态、记忆及待确认建议 | 本局`.sav`中的`SAVESTR:61`快照 |
| 已采用的原始对话 | 本地`数据/记忆/<剧本编号>.json`，并通过`SAVESTR:60`随存档保存与恢复 |

当前运行中的快照不等于已经落盘的存档。新游戏使用自己的初始状态与空历史；旧存档缺少完整历史快照时，只能恢复该档已有记录。详细读写与兼容约定见[开发说明](开发说明.md)。
