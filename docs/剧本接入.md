# 剧本接入与框架边界

框架提供显示、声音、模型连接、AI协议校验、物品快照、掷骰结果解析、存档和历史服务。人物、物品的含义、行动、时间消耗、每日结算与结局属于剧本。添加剧本不需要修改 `SYSTEM_*.ERB` 或重新构建运行程序。

## 一个剧本就是一个文件夹

放在 `游戏/ERB/script/<剧本名>/`。其中 `剧本.json` 登记身份、ERB入口、人物归属和可选规则；其余ERB文件由作者组织。人物卡、物品卡是内容模板，并非框架要求所有剧本都具有同样玩法。艾拉剧本的世界背景与开场已合入剧本.json的content，人物登记在characters中，汇率与每日消耗在parameters中维护；剧本接口.ERB只负责读取与提示词拼接。

现有《艾拉的奇幻冒险》新增了：

- `剧本.json`：登记、角色归属、默认建议、明确行动指令、时间参数、狩猎骰表、收益与简短记录模板。
- `生命周期.ERB`：新游戏初始化、读档迁移、回合结束、存档标题和原函数名的兼容适配。

只有上述剧本包了解“艾拉”“食材”“狩猎”及历史编号 `rain_room`。内部编号保持稳定，不能为了改显示名称随意改编号。

## 最小登记示例

```json
{
  "format_version": 1,
  "id": "my_story",
  "name": "我的剧本",
  "author": "作者",
  "type": "测试",
  "version": "0.1",
  "entry": "MY_STORY_START",
  "resume": "MY_STORY_RESUME",
  "init": "MY_STORY_INIT",
  "owners": {"player": "主角", "merchant": "商人", "world": "无主"},
  "reply_label": "剧情",
  "default_suggestions": ["观察周围"]
}
```

相应ERB函数必须定义在这个剧本文件夹中。`entry` 和 `resume` 必填；其他生命周期函数按需要填写，空缺时框架不添加默认玩法。以下是可运行的最小流程：

```erb
@MY_STORY_INIT
DAY = 1
TIME = 0
RETURN 1

@MY_STORY_START
$MY_STORY_MENU
CLEARLINE LINECOUNT
CALL APPLY_DISPLAY_SETTINGS
DRAWLINE
PRINTL 我的剧本
PRINTL [1] 保存进度
PRINTL [2] 读取进度
PRINTL [0] 返回标题
ESCAPE 0
INPUT
SELECTCASE RESULT
    CASE 0
        RETURN
    CASE 1
        SAVEGAME
    CASE 2
        CALL LOAD_SCENARIO_SAVES, "my_story"
ENDSELECT
GOTO MY_STORY_MENU

@MY_STORY_RESUME
CALL MY_STORY_START
RETURN
```

添加或移走整个剧本文件夹后重启游戏，以载入或卸载ERB函数。登记缺损、入口不存在、编号重复会在选择页提示；编号重复的包都不载入。ERB沿用引擎的统一解析和执行环境，因此作者必须使用不同函数前缀，ERB语法错误仍需修复。这里是模块边界，不是运行不可信代码的沙箱。

## 生命周期

| 登记字段 | 调用时机 | 返回约定 |
| --- | --- | --- |
| init | 开始此剧本的新游戏 | 初始化本剧本状态；成功 RETURN 1，失败 RETURN -1 |
| entry | 新游戏初始化后 | 显示本剧本操作流程；返回即结束本次入口调用 |
| resume | 读档恢复完成后 | 继续操作流程，不能重新发放初始物品 |
| before_save | 手动保存说明生成前、自动保存前 | 把本剧本外部状态写入存档字段；成功1、失败-1 |
| after_load | 引擎恢复存档后 | 校验、迁移并恢复历史等本剧本状态；成功1、失败-1 |
| turn_end | EVENTTURNEND | 本剧本决定是否推进时间、扣资源或进入结局 |
| save_caption | 生成存档标题时 | 将说明写入 RESULTS:0，成功返回1；未提供时用剧本名称 |
| legacy_probe | 旧存档没有剧本编号时 | 本剧本负责识别；匹配返回1，否则0；只有唯一匹配才采用 |

通用层仅保留 `SAVESTR:0` 作为本局剧本编号。其余FLAG、SAVESTR数据由当前剧本定义含义并随存档保存。每次只有一个活动剧本；不同剧本可以复用同一状态下标，但必须在自己的init里初始化，不能把本局状态写成公共全局设置。`GLOBAL`、配置、显示和模型连接是共用的，不用于保存不同剧本的本局库存。现有艾拉剧本的旧GLOBAL用法保留兼容，由自己的生命周期恢复。

## 物品与AI服务

物品编号没有全局含义。编号2可以是导航图，不会自动被当成食材。归属来自本剧本的 `owners`，ID可使用1～64位英文字母、数字、下划线和短横线；显示名称可中文。单个物品可分布在多个已登记归属中。

`AICONNECTION` 保留现有指令名；下表是给剧本作者的接口。调用失败时 `RESULT=-1`，`RESULTS:0` 为错误提示。所有输入必须先设置，避免沿用上一轮RESULTS数组。

| 编号 | 输入 | 输出/作用 |
| --- | --- | --- |
| 30 | 无 | RESULTS:0为空物品表，包含当前剧本归属登记 |
| 31 | 0快照；1编号；2名称；3描述；4类型；5属性；6数量；7归属ID；8短摘要 | 返回添加初始物品后的快照，仅本地构建初始表使用 |
| 32 | 0快照；1物品ID；4逗号分隔的归属ID（空表示全部） | 0快照；1合计数量；2物品种数；3修订号 |
| 33 | 0快照；1数量；2物品ID；3归属ID | 旧档迁移时替换此物品的数量分布；保留物品定义 |
| 34 | 0快照；1玩家输入 | 准备本剧本本轮完整快照；返回相关物品摘要，实际发送时由原生层统一筛选物品、状态及场景 |
| 35 | 0原快照；1本轮候选快照 | 校验下一修订并返回可提交快照，不再隐含返回食材数量 |
| 36 | 0快照；1消耗数量；2物品ID；3按优先顺序的归属ID列表 | 最多扣至零；0新快照；1所列归属的剩余量 |
| 37 | 0快照；1物品ID | 0名称、1描述、2类型、3属性、4持有情况、5编号 |
| 38 | 0快照；1从0开始的页码 | 0～9列表行、10页数、11物品种数 |
| 40 | 0快照；1已确定骰点；2行动key | 根据登记的骰表返回0摘要、1收益数量、2简短记录、3AI规则 |
| 41 | 0快照；1已确定骰点；2行动key | 为下一次AI请求准备程序控制的行动结算 |
| 42 | 0快照；1已确定骰点；2行动key | 使用相同骰点本地结算，返回0快照、1记录、2变化摘要 |
| 43 | 0建议JSON | 返回当前建议或本剧本默认建议；RESULT为数量，RESULTS:0～2为内容 |
| 44 | 0玩家输入 | 返回本剧本commands登记的明确行动编号；0表示普通输入 |
| 45 | 0参数key | 返回当前剧本parameters中对应的整数值 |
| 46 | RESULT为从0开始的页码 | 自动发现登记，RESULT为总数；0～19菜单文字、20～39对应ID、40登记错误 |

| 48 | 0存档标题；1剧本ID | RESULT表示标题是否匹配此剧本 |
| 49 | RESULT为从0开始的登记序号 | 激活对应剧本，返回同47的元信息 |

47/49的输出依次为：0编号、1名称、2entry、3resume、4init、5before_save、6after_load、7turn_end、8save_caption、9legacy_probe。

先用34或41准备，再调用AISTART；其剧本编号必须一致，否则请求被拒绝，不能把另一个剧本的库存附到本次请求。普通物品操作继续走玩家确认流程；无物品变化无需确认，登记的程序行动自动结算。程序行动的骰子必须由剧本先掷定并保存，41/42不会重新掷骰。模型不能追加程序行动的物品收益。

AI协议只解释增减、创建、转移这些通用操作，不在框架里包含每日扣粮、狩猎、角色名称或固定归属。剧本专用限制写在 `inventory_instruction`；每个行动的额外规则、保底记录和可选数量检查表达式由 `actions` 配置。当前规则解释器支持每次行动对一个指定物品、一个归属发放非负收益；更复杂的战斗、交易和多物品结算应由本剧本ERB组织，不能靠文字假装已经实现。

## 存档与历史隔离

- 正常存档按稳定剧本编号保存到 `游戏/数据/存档/<id>/saveXX.sav`（使用自定义存档根目录时相对于该目录）。各剧本都有独立的同号手动存档和99号自动存档。
- 新存档标题带有 `[scenario:<id>]`，读档按编号分组，不依靠人类可改的显示名称猜测。
- 旧根目录的 `saveXX.sav` 不移动、不删除。当前剧本目录没有同槽存档时，读取符合本包 `legacy_save_labels` 的旧档；新保存写入剧本目录，不覆盖旧根目录文件。已有新槽位后优先显示新槽位。
- 活动对话记忆仍按ID保存在 `数据/记忆/<id>.json`。本剧本可用20/21/22号历史接口把记忆快照绑定到自己的存档字段。显示回复标签来自 `reply_label`。
- 存档记录当前实例，而不是复制所有初始ERB文件。正常修改初始物品卡不会回写已存在的存档；改变物品编号、删除归属或改变状态字段时，需要本剧本提供迁移方案。

## 验证

运行 `测试.ps1 -Scenario`，包含通用核心测试和剧本集成测试。独立轨道站测试只存在于测试临时目录，不作为第二个正式剧本加入游戏。

实际验证：新增第二个剧本而不改框架；与艾拉同时安装；移走艾拉仅保留第二剧本；移走全部剧本；不同角色与编号2物品；另一剧本AI物品结算；存档/生命周期/历史标签；各剧本同号自动存档不互相覆盖；艾拉旧档别名与物品快照迁移。

## 人物状态与统一资料读取

`characters` 为人物编号到显示名的映射，与物品 `owners` 分开登记。仅允许为已登记人物创建持续状态；无主、仓库等物品归属不必登记成人物。未登记人物状态功能的旧剧本默认空人物表，原有物品协议继续可用。

`content` 为作者维护的文字资料键值表；`parameters` 为整数规则表。框架没有写死艾拉的背景、人物、货币或伤病规则。`AICONNECTION 50` 读取当前剧本的 content 键（输入RESULTS:0）；51返回编号、名称、作者、类型、版本（RESULTS:0～4）。原45仍读取parameters。

人物状态与物品共用SAVESTR:61候选快照和回合版本，接口34准备完整快照，原生层在发送时按参与人物补充有效状态，35统一提交。52按页查询状态（输入RESULTS:0为快照，1为零起始页；输出0～9列表、10总页数、11条数）；53查询详情（输入0为快照，1为状态编号；输出名称、人物显示名、类别、程度、描述、影响、发生时间、更新时间）。52/53是只读查询。

默认受控行动不允许AI追加状态操作，已有状态则原样保留。其他剧本可独立登记自己的characters、content与行动规则；不要在通用框架中添加具体人物或药物规则。


## 请求资料与当前场景

结构化剧情请求的system只放稳定任务与输出协议；历史只含已采用的玩家输入和剧情。最终user是JSON：`program_context`保存程序事实，`player_input`保存玩家原话。回合标识、修订号、当前场景、相关物品和状态由原生层从本局完整快照组装；不要在ERB材料里重复玩家输入、整张初始库存或开场全文。

`context_selection`由各剧本配置：`item_aliases`是物品数字编号到别名数组，`related_items`是编号到关联编号数组，`action_items`是行动关键词到相关编号数组。原生层还匹配保守中文短称；涉及指代时参考最近已采用对话与已提交物品焦点。筛选在本地完成，不另调模型。发出的局部表标明`complete:false`，未列出不代表不存在；合法性仍对完整快照校验。筛选不能完整理解全部自然语言，歧义应澄清，不猜编号。

当前场景是可选的`scene:{location,present_characters,summary}`，与库存和人物状态共用存档快照；不是地图或事件系统。`initial_scene`供新游戏初始化，骰子行动可配置`end_scene`；`action_locations`可为hunt/sleep/rest配置允许的场景卡编号。当前入眠和短休接口在原地完成，不依赖旧local_scenes传送。旧档缺少场景时保留未知，不自动认定仍在开场地点。框架不保存具体剧本的人名、物品或地点。

| AICONNECTION | 输入RESULTS | 返回 |
| --- | --- | --- |
| 54 | 0精简剧本人物资料；1时钟等当前事实；2本轮相关规则 | 0为安全转义的JSON材料，供AISTART第一参数传入；原话单独传第二参数 |
| 55 | 0完整快照 | 0当前地点（未知时明确标注）；1当前场景摘要，只读 |
| 56 | 0完整快照；1仅接受旧rest键名 | 兼容旧入眠入口，按sleep地点限制原地执行，不再读取local_scenes传送 |
| 57 | 0完整快照 | 套用initial_scene并返回快照；只应由显式新游戏初始化调用，旧档迁移不得调用 |

模型可增加`scene_update:{location,present_characters,summary,reason}`，全部字段必填，人物必须已登记，摘要最多600字符；省略时保留原场景。地点或在场人物改变进入普通统一预览，仅摘要更新不强加确认。任一物品、状态或场景操作无效则整轮拒绝，场景也不部分提交。程序行动禁止模型追加scene_update，结束场景由登记配置写入。


## 场景卡与本地历史摘要

可通过登记项world_file引用剧本目录内的场景卡JSON（format_version:1、scenes数组）。每卡含id、name、description、adjacent数字列表、facilities、aliases及rules；编号、名称和别名不得冲突。未配置时框架仍支持原自由地点文字。

场景定义首次复制到存档后，本局维护KnownScenes、CharacterLocations及SceneConditions；不因修改初始卡而重写本局。通用物品、状态、场景和历史记忆均由SAVESTR:61保存，不需要剧本维护另一份数量或位置表。

框架ERB/历史记忆.ERB提供NATIVE_MEMORY_PAGE；需要在剧本行动页显式调用。70至78桥管理已确认/待确认摘要，79读取最近已采用对话供玩家摘录，不会调用AI。选物服务60/61展示资料及可处理伤势，62为下一次请求准备显式所选物品；80只读场景资料。所有待采用模型结果仍通过35做版本校验后提交。

63可关联在场同伴实际持有的物品，不会自动转交给主角；明确包扎仍须由主角持有材料。输入输出和使用方式详见[剧情输入与本地状态](剧情输入与本地状态.md)。

## 多选物品与行动可用性扩展

- `64`：0快照、1所选物品编号CSV；附加本轮相关物品，保留已准备的受控狩猎或包扎计划，仅同一剧本及完全一致的快照可复用。
- `85`：0快照、1页码、2已选CSV、3browse/select；绘制名称矩阵。返回0页数、1物品数、2已选名称、3列数、4纠正后页码；browse按钮值10000+物品编号，select字符串payload为@item:编号。
- `86`：0快照、1天、2时间格、3最后狩猎日；返回0..3自由/入眠/狩猎/短休可用标志，4..7对应原因。
- `87/88`：0快照，按地点限制分别完成原地短休/入眠；返回0新快照、1正文。调用方随后推进时间并日结。
- `89/90`：人物概览/人物持续状态分页。均只读，原伤势详情仍用53。
- `91`：0快照、1已选CSV、2物品编号；验证并切换选择，返回新CSV，不写快照。
- `92`：0快照；按可选item_text_migrations_file执行精确默认文字迁移，返回新快照。只改完全匹配的原描述/属性，不动自定义内容、数量与版本。
- `94`：0快照、1已选CSV、2单个规范数字编号；验证该物品已选且为主角持有的包扎材料，不执行消耗。

允许地点属于剧本资料，框架不内置具体猎场或人物名称。文字迁移表也放在剧本目录；移植其他剧本时不需要保留本测试剧本的物品迁移。

## 数量选择扩展

64与85的选择字符串兼容原有编号CSV，新写法为id:数量,其他id:数量；空字符串表示未选。91的0快照、1选择字符串、2物品编号、3增量（-1/+1/-10/+10），返回新选择；左键+1选择或增加，右键-1减少，减至0取消；未选时负向调整保持未选。所选数量只保留本次输入页，不写入状态快照。95输入0已用格、1总格，按当前字体和配色输出矢量平行四边形时间格，不创建按钮。
